# Say it plainly

The user wants something rewritten so a reader without this thread's
context understands it on first reading.

1. **Pick the text.** The last answer, unless the user named something else.
   If they named a reader ("for Rich", "for the client"), write for that
   person. If they just didn't follow it themselves, write for them.

2. **Keep every fact.** Don't drop a caveat, a number, a date or a decision
   to make it shorter. If something in the original was wrong or unclear,
   check it and fix it, and say you did.

3. **Rewrite it.**
   - **Bottom line first**, in one or two sentences: what happened, what it
     means, what (if anything) the reader has to do.
   - **Then the detail**, short paragraphs, everyday words.
   - **Explain each technical term once**, the first time it matters, in a
     few words ("a pull request, the proposed change waiting for approval");
     drop jargon that isn't needed.
   - **No thread shorthand.** Ticket ids get their exact title; "the bug we
     found" becomes what the bug was. Times in Mountain time.
   - **Match the reader**: for a client, nothing internal they shouldn't
     see (other clients, costs, internal disagreements) and no secret values.

4. **Answer** with the rewritten text, ready to copy. If it's going to
   someone else, one line first naming who it's written for, so the user can
   correct it.
