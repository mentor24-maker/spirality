## 2026-11-03 — A ticket stays in Building forever when its build pass dies: put it back in the queue (#79)

When a build pass stopped partway, for example because it was killed or ran out of time, the ticket it had taken stayed marked "Building". No loop picks work up from "Building", and every later pass assumed someone was still working on it. That is how SP-92 sat untouched for a day until a person noticed.

The first version used a timer: put a ticket back after 90 quiet minutes. Review found that a timer can't tell a dead loop from a person working slowly by hand. It also missed comments as activity, and it never caught a dead pass on a ticket that was already being reworked. Dane chose the safer design instead.

Now, when the build loop (and only the build loop) takes a ticket, it leaves a small marker saying "I took this one". Handing the ticket on removes the marker. The next build pass starts by reading it: if the marked ticket is still in "Building", the pass that took it is gone, so it goes back. A ticket with a pull request goes to Rework, so the next pass finishes that pull request. A ticket without one goes to Queued. Either way it gets a note naming when it was taken and any leftover work folder. There is no timer, and nothing is deleted. A session Dane runs by hand never leaves a marker, so its ticket is never taken away from it.

The second review found two ways the marker could still go wrong. If putting a ticket back failed, the same pass's next claim wrote its own marker over the old one, and the stranded ticket was forgotten again. Now a claim refuses to write over a marker whose ticket is still stuck, and the pass stops and says so. And if a claim lost a race to someone working by hand, its marker stayed behind naming that person's ticket, so the next pass would have taken it from them. Now a refused claim removes its own marker. The note on a put-back ticket also no longer says "no leftover work folder was found" when the folders could not be listed at all.
