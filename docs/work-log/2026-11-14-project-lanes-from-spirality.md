## 2026-11-14 — Run a project's lanes from Spirality's folder (#242)

Until now, every project ran its loop jobs (the build, review and intake lanes and the relay) from its own copy of the loop code. Spirality's installer can now set them up to run Spirality's code instead, working in the project's folder. Each pass still happens inside the project, so the project's own rules and checks still apply. Each pass picks up the project's newest merged work and never Spirality's, so new Spirality code never reaches a project in the middle of a pass. `--status --project <folder>` shows, for each job, which program it runs and in which folder. `--print-plists` shows the files an install would write, without writing them. Nothing has been switched over yet. Replacing a project's own jobs needs an extra `--take-over` flag, on purpose, because switching a project over is Dane's decision. Spirality's own jobs are unchanged.

After review, three gaps were closed. The check that stops a project from taking Spirality's own job names now always reads Spirality's names from Spirality's folder, so it gives the right answer wherever the installer is started from. Removing a project's jobs while they still run the project's own copy is refused without `--take-over`, the same as installing over them. And `--project=~/...` now works like `--project ~/...`.
