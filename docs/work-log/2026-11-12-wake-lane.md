## 2026-11-12 — A ticket waits up to 30 minutes for the next lane to wake: start the next lane when a ticket changes status (#191)

The build, review and intake loops each wake on a 30-minute timer, and the
relay every 10 minutes, so a ticket that has just moved on could sit
idle until the next loop woke up by itself. This change lets a loop be woken
early, safely.

Between passes, each loop now checks every few seconds for a small "wake"
file. When one appears, it starts its next pass straight away and notes in
its log that it was woken. It only checks between passes, so a pass is never
cut short. A wake that arrives mid-pass waits, and exactly one more pass runs
as soon as the current one ends. The relay runs one pass per start, so it is
woken with a start that never runs a second copy alongside one already
running.

A new command, `node scripts/lib/wakeLane.mjs <loop>`, sends the wake and
says in one line what it did, or why it could not. The timers are unchanged
and still run if nothing sends a wake. The next slice (SP-231) has the
tracker send the wake whenever a ticket changes status.
